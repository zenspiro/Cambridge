## Security baseline (already in place)
- `src/middleware.ts` sets a per-request CSP nonce and the headers from `src/lib/security/headers.ts` on every page and API route. Static files get theirs from `public/_headers`. Any outside host must be added to `buildCsp` on purpose.
- We use `middleware.ts` (edge) rather than Next 16's `proxy.ts`, because OpenNext marks Node middleware as experimental. The build prints a deprecation notice for it; that is expected.
- Every page is rendered per request (the layout reads headers), which the nonce needs.
- Errors: `reportError()` and `publicErrorBody()` in `src/lib/errors.ts`. Visitors see a reference only. Page errors show Next's digest as the reference.
- `npm run check:inline` blocks inline styles, HTML event handlers, raw HTML, eval, script tags and browser dialogs in `src/`. Counts live in `scripts/inline-baseline.json` and may never grow. React props like `onClick` are fine.
- Access: every `page.tsx` and `route.ts` either calls `requireAdmin()` / `adminSession()` (`src/lib/auth/guard.ts`) or is listed in `PUBLIC_ROUTES` (`src/lib/access.ts`). `tests/unit/access.test.ts` enforces it.
- Forms: plain POST to a route handler, then a 303 redirect (`redirectTo` in `src/lib/http.ts`, same-site paths only). Every POST checks `isSameOrigin`. Messages travel as fixed codes (`?e=bad`), never as text.
- Admin frame (owner, 6 Nov 2026): `AdminShell` is a sticky left sidebar in groups (Home; Library: Library, Upload, Sources, Agent; Subject brain: Topic trees; Students and parents: Parent approval; Settings: Library settings, AI setup, Brand, Themes) and the page uses the rest of the width (`.admin`, `.admin-side`, `.admin-main`). `current` names the item a page belongs to. Desktop only.
- No page reloads unless necessary, never browser popups (owner, 5 Nov 2026): small actions use `ActionForm` (`src/components/ActionForm.tsx`, client): it posts the same form in the background, reads the message code (`e`, `r` or `f`) from where the redirect lands, shows it beside the button and calls `router.refresh()` (same scroll, folded sections stay). `confirm` asks inline (Yes / Never mind). Used on the Sources page (switch, remove, add) and the run page (Accept, Reject, Undo, Rename, Remove). Without scripts they are still plain forms.

## Library hierarchy and checklist
- Hierarchy: `qualification` (IGCSE, O Level, AS & A Level) > `subject` (`qualification_id`) > syllabus code > `syllabus` versions > `source_document`. Subjects are seeded by migration (0003, 0011); adding one from the panel ("Find on Cambridge") is not built yet; empty qualifications still show. `listSubjects()` (`catalog.ts`) gives pickers their names ("IGCSE Physics (0625)").
- Components marked by the school (coursework, speaking: `syllabus_paper.school_assessed = 1`, migration 0011) are shown with their papers but never in `expected.papers`. `inPapers` in the rules asks for an insert per paper (essential, like the paper); tables show only the columns a syllabus uses.
- Subject map (owner request 4 Nov 2026, option A): `buildSubjectMap()` (`src/lib/library/map.ts`, pure) groups the checklist by syllabus version: its documents and specimens, then each exam session (newest first) as a row with papers as column groups (QP, Insert, MS, CI, only the types the paper has) and ER, GT; essential variants only unless `?variants=all`; school-assessed components named below. `SubjectMapVersion` (`src/components/SubjectMap.tsx`) draws it above the search box. `subjectMapJson()` gives the same hierarchy as JSON with each file described in words: served by "Download map" (`/admin/library/[code]/map`, admin, attachment, no-store) and by the signed `/api/agent/catalog` for the AI.
- `buildChecklist()` (`src/lib/library/checklist.ts`, pure) lists every expected file: per version the syllabus (essential), update and grade descriptions (extras) and specimens; per public session each paper and variant (qp, ms, ci for paper 5) plus er and gt. Rules are JSON in `syllabus.expected`. Essential variants: see below (variant 2). Stored files the checklist does not ask for show under "Other stored files".
- `loadCatalog()` / `loadSyllabus()` (`src/lib/library/catalog.ts`) read the tree; the admin library and the signed `/api/agent/catalog` (for the AI engine, metadata only) both use them.
- Search: every word must match; numbers match whole words (so "4" is paper 4), other words match word starts, file names match inside. Filters: year, session, type, paper, status (missing essentials, stored, extras).
- Cells: green tick downloads; red cross (essential) or grey + (extra) opens the add page. Adding by upload renames to the checklist name; by link only from an enabled source (robots.txt, same-site redirects, size cap; `fetchApprovedPdf`). Origin `link`.
- Papers: `syllabus_paper` (number, name, format mcq / structured / practical / written, tier core / extended / all, time, marks, weighting) and `syllabus_route` (Core 1 + 3 + (5 or 6), grades C to G; Extended 2 + 4 + (5 or 6), A* to G) per version, migration 0007, checked against Cambridge's 2023 to 2025 and 2026 to 2028 syllabi; 2020 to 2022 rows say not checked. `src/lib/library/papers.ts`: `loadPapers`, `describeFile` ("June 2024, Paper 2 Multiple Choice (Extended), variant 2, mark scheme"), `routeText`. The catalog API carries papers and routes.
- Essential variants: `syllabus.essential_variants` (per code, set on the overview) wins; else the library default in Settings. Both are variant 2 now.
- D1 refuses long `UNION ALL` chains in one statement ("too many terms in compound SELECT"); seed with `WITH x (...) AS (VALUES ...)`. A migration test enforces it.
- New types `su` (syllabus update) and `gd` (grade descriptions): `0625_y23_su.pdf`. Migration 0006 rebuilt `source_document` for them, a one-time owner-approved exception to additive only (allowed by name in `tests/unit/migrations.test.ts`).

## Acquisition agent (build 3b)
- Run button: `/admin/agent` (subject, years, sessions incl. Specimen, dry run or download; nothing ticked in years or sessions means all of them (owner, 5 Nov 2026); `?code=` picks the subject, linked from each subject's library page; any code in the library is accepted by `checkRunParams`) creates a `job` of type `agent` (one at a time, checked inside the insert; runs silent for 15 minutes are closed) and calls GitHub `workflow_dispatch` on `.github/workflows/agent.yml` (`src/lib/agent/github.ts`). Report page: `/admin/agent/runs/[id]`; a dry run offers "Download these N files".
- Agent: `scripts/agent/run.ts`, Node built-ins only (no npm install in Actions). Reads its run from `/api/agent/job`, reads robots.txt first (missing means allowed, unreachable means nothing allowed), visits only the start pages (`source_page`, edited on `/admin/sources`), follows PDF links inside the source's address, waits 5 s between requests, never follows redirects off the site, sends each PDF to `/api/agent/file`, reports to `/api/agent/finish`.
- Name translation: `toCambridgeName()` in `src/lib/agent/links.ts`, built from Cambridge's real names (`570010-june-2024-question-paper-11.pdf` to `0625_s24_qp_11.pdf`; specimens and syllabi too). Unknown links go in the report, never guessed.
- `/api/agent/*` have no session: every request must pass `agentRequest()` (HMAC-SHA256 over time, nonce, method, path and body hash; 5 minute window; nonce spent once in `request_nonce`). Files must come from an enabled source's address, at most 400 per run, and go through `storeDocument()`.
- Secrets (owner sets them, never in code): Worker `GITHUB_TOKEN` (Actions read and write on this repo only), Worker and GitHub `AGENT_SECRET` (same value, 32+ characters). Vars in `wrangler.jsonc`: `GITHUB_REPO`, `AGENT_WORKFLOW`, `AGENT_REF`. Local: `.dev.vars`.
- Live feedback: the agent posts signed updates to `/api/agent/progress` (progress, step, event, its GitHub log link); `recordProgress()` keeps the last 120 events and a heartbeat. A 409 there means cancelled or closed, and the agent stops. The run page reloads itself every 10 s while active (`<meta http-equiv="refresh">`, no script), shows a progress bar, elapsed time, activity log, GitHub log link and Cancel (inline confirm).
- Activity in plain words: the agent sends structured events (`text`, and for a file `file`, `outcome`, `reason`, `bytes`; checked by `cleanEvent()`), page lines use the page's own title (`pageTitle`) and `summariseFiles()` ("June 2024: 6 question papers, 6 mark schemes"). The run page describes file events with paper names (`describeFile`), groups the file lists by session, and ends with "Library after this run" (or "What a download would add"): each session touched, essential vs extras, its status and a link. Up to 120 events kept per run.
- `closeStaleRuns()` (on start and when agent pages load): no sign of life for 15 minutes closes a run as `never_started` (GitHub never ran it, usually the GitHub secret) or `timeout`. A queued run older than 5 minutes shows a warning.
- Google Drive sources: a `source_site` with address `https://drive.google.com/` gets `kind = 'gdrive'` and holds `source_drive_folder` rows (pasted in bulk on `/admin/sources`; `driveFolderId()` reads the links). The agent (`scripts/agent/drive.ts`) walks each folder tree through the Drive API v3 with the GitHub secret `GOOGLE_DRIVE_API` (sent as the `X-Goog-Api-Key` header, never in a URL), 1 s between calls, up to 2,000 folders and depth 8 per run, backs off on rate limits, follows shortcuts. Downloads (owner report 4 Nov 2026: 25 stored, then 346 refused with 403): one every few seconds; a refusal is recorded with Google's reason (`driveRefusal()`: `drive_quota`, `drive_rate`, `drive_forbidden`, `drive_missing`, words in `DRIVE_REASONS`, `src/lib/agent/labels.ts`); a quota or rate refusal waits 30 s and tries once more; after 5 refusals in a row the run stops asking Drive (`report.drivePaused`, the rest `drive_paused`) and the summary names it as a limit. A later download run picks up the rest. `classifyFile()` (`src/lib/agent/classify.ts`) works out each PDF's Cambridge name from the file name, then the folder names (subject by code or by name and qualification, year, session words like "May June", type words like "Mark Scheme", paper and variant like "Paper 4 Variant 2" or "42"), with confidence and the reason; unclear files are reported, never guessed. Codes are read from brackets ("(0478)", never a year) or when they are library codes; a bare number like "1524" is never a code. A run reads only the folders for its own subject: a folder whose label (or Drive name, if unlabelled) names another code is skipped without a call to Google (`driveSkipped` in the report). The run report has a per-folder reading ("looks like IGCSE Physics 0625", PDFs, years, other subjects) saved to `source_drive_folder.last_seen` for the Sources page. Drive files are stored with source URL `https://drive.google.com/file/d/ID/view`; `/api/agent/file` accepts only that form for a Drive source.
- Folder choice (owner request 4 Nov 2026): `walk()` takes a `choose` hook; `folderDecision()` (classify.ts) says yes / no / unsure per subfolder name (another subject, a year or session outside the run, specimens only when the run asks). Below a matched folder, unclear names open. Each Drive summary reports `skippedFolders` and `yearsHeld`.
- Workers AI (owner decision 4 Nov 2026, option A): binding `AI`, model in the var `AI_MODEL` (`@cf/meta/llama-3.1-70b-instruct`, JSON mode). The agent never talks to the model: it calls the signed `/api/agent/ai` with a task (`folders`: unclear subfolder names; `names`: files the rules could not name; `summary`: rewording of a draft). Prompts, schemas and answer checks are in `src/lib/agent/ai.ts`; the run, scope and caps in `aiTask.ts` (running run only, `AGENT.aiCallsPerRun` 80 per run through `allow()`, 40 items per call). The model gives parts; the name is built here (`readNames`) and kept when it is the subject's file in the run's years and sessions, whether or not the checklist asks for it (owner decision 4 Nov 2026); a real file outside them is `not_needed` with its name (never auto-rejected, so a later run for that year takes it); parts that make no name go to `report.review` ("Needs your eye"). `wantedNames` is still what Accept on a run page may choose. File names go to the model as numbered data. 503 (no AI, local dev), 429 or three bad answers switch AI off for the run and the rules carry on; the run page says so. The run page shows `report.summary` at the top. Summary (owner decision 4 Nov 2026, option A): `ruleSummary()` (`src/lib/agent/runSummary.ts`) writes the facts, names only real limits (Drive folder truncated, more files than one download) or says "Nothing was cut short"; the AI may only reword it, and `checkRewrite()` drops any rewording that adds or changes a number or talks of limits the draft does not have; then the draft is shown.
- Needs your eye (owner request 4 Nov 2026): Drive files nobody could place (rules or AI) go to `report.review` as items `{where, why, driveId, siteId, suggest?, by}` (up to 200; old reports hold strings, shown only). The run page (`ReviewList`, `src/components/ReviewList.tsx`) offers Accept (choose which of this run's missing checklist files it is, `acceptChoices`) or Reject, and Undo; POST `/admin/agent/review` with the run id and the item's position, so the item is read from the report, never the form. `decide()` (`src/lib/agent/review.ts`) checks the name is wanted, not stored and not chosen for another file, writes `review_decision` (migration 0012, one row per Drive file, one file per accepted name) and audits `review.accept|reject|undo`. `/api/agent/job` sends the decisions; the agent applies them before its rules (accepted: that name; rejected: skipped, `report.rejected`, named in the summary). "Download accepted files" starts a download with the run's choices.
- Front page reader (owner decision 4 Nov 2026, option A): `firstPageText()` (`src/lib/pdf/firstPage.ts`, own small reader, no libraries, `inflate` passed in: zlib in Node, DecompressionStream later in the browser) gives page 1 text; `readCover()` (`src/lib/library/cover.ts`) reads code/component, session and year, type (the heading that appears first wins; capitals matched exactly) and builds the name with `nameFromParts()` (`names.ts`, shared with the AI). It runs in the agent on GitHub (Cloudflare's free plan CPU limit is too small for PDF parsing). Download runs: unclear Drive files (up to `AGENT.coverReadsPerRun` 60) are downloaded and named from their cover, then the AI `cover` task; AI `not_needed` becomes an automatic reject (`review_decision.decided_by = 'agent'`, written by `/api/agent/finish`, never over the owner's decision). Every download is checked: a cover naming another missing file of the subject stores it under that name (`report.renamed`), otherwise it is held back (`cover_mismatch`, to Needs your eye). A file with no readable cover is stored as before. Mode `check` ("Check library"): `/api/agent/job` sends `storedDocs`, the signed `/api/agent/doc` returns one stored file (running check run, same subject), mismatches go to `report.check.items`; the run page (`CheckList`) offers Rename (`renameDocument`, moves the R2 object) or Remove (`removeDocument`), POST `/admin/agent/fix`, audited `source.rename` / `source.remove`. Real cover lines of 11 Cambridge files are test data (`tests/unit/fixtures/covers.json`); `tests/unit/helpers/pdf.ts` builds test PDFs. A bare 403 on a Drive download is `drive_throttled` (Google limiting signed-out downloads); the agent stops asking Drive after 3 refusals in a row.
- Upload a folder (owner request 4 Nov 2026): `/admin/library/folder` (`?code=` main subject) renders `FolderUpload` (`src/components/FolderUpload.tsx`, the app's first client component) as one card: the subject picker (changes `?code=` with `router.replace`, no button) and the folder. The browser picks a folder (`webkitdirectory`, set in an effect; Chrome then asks "Upload N files to this site?", which a site cannot switch off) or the folder is dragged onto the card (`filesFromDrop`, no browser question), and `folderPlan.ts` (`src/lib/library/folderPlan.ts`, pure) decides each PDF: `planFromNames` (classifyFile on the relative path), `applyCover` (first page read in the browser with `firstPageText` and DecompressionStream; the cover wins over names that disagree), `applyAi` (POST `/admin/library/folder/ai`, tasks `cover` and `names` through `aiJudge()` in `aiTask.ts`, scope: the main subject, every library year; `LIBRARY.folderAiPerHour` 80, 60 calls per folder), `finalise` (new, have, outside years, unknown subject, duplicate, too big). Files from a year outside the library (`yearHint()`: a session code like `w02`/`j21` in the file name or a year in the folder names; or the cover's year) are "outside" at once: never read, never sent to the AI. An AI answer naming an old file is shown as outside the years, not as unsure. Repeats: the same name twice keeps the best evidenced file (`PlanItem.evidence`: 0 own Cambridge name, 1 folder names, 2 first page, 3 AI; then folder order); an identical size is a repeat (`dupOf`), a different file goes to Needs your eye. Each row shows one plain sentence (`noteFor()`; the technical reason stays in `why` for the report). A first page that renames a file to a name another file in the folder carries as its own name is overruled (`coverDoubt`: a misread digit), so copies like "ms_33(1)" fall out as repeats. Rows use paper names for every subject (the page passes all `syllabus_paper` names and versions). `readCover` also reads the paper title ("Paper 2 Problem-solving and Programming"); `paperTitleChecks()` lists papers whose cover title differs from the library's name (older versions were copied from the next syllabus; 0478 2020 was fixed from its covers in 0014). The "Which file is it?" picker is its own full-width line; choices show the full place ("IGCSE Computer Science (0478) / 2020 / November / file"). When the upload ends, a summary (`#folder-done`) gives stored, not stored with reasons, already stored and left out. Needs your eye: the AI's guess is chosen already (any library subject's file in the library years, shown as "the AI's guess"); or pick one of the main subject's missing files (`acceptChoices`), or leave it out. "Download report" (preview and finish) saves a CSV of every file: folder path, file, result, library name, what it is, how, why, upload result (cells starting = + - @ are quoted with a leading apostrophe). Upload: one file per POST to `/admin/library/folder/file` (raw PDF body, `x-file-name`, admin, same origin, `LIBRARY.folderFilesPerHour` 1500), through `storeDocument()`; the route always answers JSON (anything unexpected is `storage` with a reference). The page (`sendOne`) retries a reply that is not the server's own answer (Cloudflare error page, 5xx, dropped connection) after 2, 5 and 10 s; refusals (`FINAL_REASONS`) are never retried; failures say what happened ("error 503, tried 4 times"), and the finish summary offers "Try the N failed files again" (owner report 4 Nov 2026: a run of 2020 and 2021 files all came back "could not be stored"). The model runner is shared: `makeModelRun()` (`src/lib/agent/model.ts`).
- AI meter (owner request 4 Nov 2026, option A): `makeModelRun()` records every question in `ai_usage` (migration 0013, one row per UTC day: calls, tokens as Workers AI reports them or estimated, neurons estimated with `AI_USAGE` in `config.ts`, rates from Cloudflare's pricing table). `AdminShell` (async) shows "AI today: N questions, about X% of the free 10,000 units" on every admin page (`aiUsageToday`, `src/lib/agent/usage.ts`).
