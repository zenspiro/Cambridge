# Features

A plain list of what the platform does today, for non-developers.

## Live
- A placeholder home page.
- A health page (`/health`) that says whether the database and file storage are working.

- Admin sign-in with a password, at `/admin/login`. After 5 wrong tries from one network, sign-in pauses for 15 minutes.
- Admin home showing recent activity.
- Library (admin only): Cambridge files organised by qualification (IGCSE, O Level, AS & A Level) and subject. Each subject has a status bar: green when every essential file is in. 16 IGCSE subjects are in: Physics, Mathematics, Biology, Chemistry, ICT, Computer Science, Geography, Business Studies, Accounting, Economics, French, Literature in English, English First Language, History, Global Perspectives and Enterprise. Coursework and speaking parts are listed as marked by the school; inserts count where a paper comes with one.
- Inside a subject: an overview with the status, the sessions missing most, a subject map (every syllabus version with its documents and specimens, then every session with each paper's files, ticked or missing; "Download map" gives the same as a file for the AI), and the papers (for example Paper 2: Multiple Choice, Extended) with the Core and Extended routes. Search and filters give a short list described in plain words.
- One page per exam session: a "Read and review" list of the question papers and mark schemes held, each with a Review button and whether it was read; every paper with its name and Core or Extended tag; a green tick opens the review screen, a red cross is a missing essential file, a grey + is an optional extra (other variants).
- Variant 2 counts as essential, because that is what Pakistan sits. Each subject can change this.
- Add any missing file from its cell: upload it (any file name) or paste a link from an approved website.
- Upload: add up to 20 Cambridge PDFs at once; wrong names, non-PDFs and duplicates are skipped with a reason.
- Approved sources: the list of websites the download agent may visit, which the admin can add to, switch off or remove, with the start pages the agent reads on each.
- Sources page: one card per subject with its Cambridge pages (and how many of their files are not in the library yet) and its Google Drive folders; add pages or folders right on the subject.
- Google Drive collections: paste shared folder links on the Sources page; the agent reads the folders, works out what every file is (subject, year, session, paper, variant) from the folder and file names, and takes only what is missing. A run reads only the folders for its own subject and skips the rest. The agent opens only folders that can hold the years and sessions you asked for, and tells you which years a folder holds. Cloudflare's AI helps with what the rules cannot read: unclear folder names, files with unclear names (only files your checklist asks for are kept; the rest go to "Needs your eye"), and a short summary at the top of every run. Under "Needs your eye" you accept a file (choosing which paper it is) or reject it; later runs remember, so accepted files are fetched under that name and rejected ones are skipped. The front page reader reads the first page of a PDF like a person would: in a download, files with unclear names are named from their cover first, every download is checked against its cover before it is stored, and "Check library" on the Run page reads the files you already hold and offers Rename or Remove for any that do not match. Pick the subject on the Run page, or press "Run the agent for this subject" on its library page.
- Download agent: pick years and sessions, do a dry run to see what it would fetch, then download only the missing files. It reads each site's robots.txt, waits between requests and never logs in.
- Live run page: progress bar, current step, time so far, and a plain-words line for every page and file (for example "Stored: June 2024, Paper 1 Multiple Choice (Core), variant 1, question paper"), a link to the GitHub log, and a Cancel button. It updates itself every 10 seconds.
- After a run: what changed in the library, session by session, with how many of the files were essential.
- Settings: library years, the latest public exam session, and which variants count as essential.
- Brand (admin): the platform name, short name, description, footer statement, the theme new students start in, and the logo, square logo and favicon. Changes show on every page at once.
- Student and parent sign-in at /signin: an emailed 6-digit code or Google. The first time, people choose student or parent and give their first and last name. Students and parents each get their own (still empty) home page, and can sign out.
- Parent approval: students who could be under 18 (or the age set for their country in Admin > Settings) wait until a parent approves by email with one tap. If the parent declines, the student's account is deleted.
- Families: parents see their children, approve waiting children from their home, add children with a family code or by making their account, download a child's data, remove a child or delete their account. Children approved by a parent by email join that parent's family by themselves.
- Me page: change your name and country, pick your theme, add your exam sessions (the home page asks once), download all your data or delete your account.
- Student themes: Bold, Playful and Clean. Same pages and words, three looks. The Themes page in admin shows every part of the student pages in each theme, in a phone-sized box, with a switch.
- Topic tree (admin, the first part of the subject brain): Library > subject > Topic tree. Press Draft and Claude copies each syllabus's topics and learning goals while Gemini copies it separately; code checks every word against the syllabus PDF. Ready trees are what later steps (question making, marking) are built on. Needs the two AI keys (see `docs/guides/topic-tree-setup.md`).
- Admin sidebar: the menu sits on the left in groups and pages use the whole screen.
- Review screen: click any green tick to see the stored PDF beside what we hold about it, switch between the paper's question paper, mark scheme and insert, and download. Next: the paper rebuilt from our database with problem parts flagged.
- AI setup: check Claude and Gemini separately, see which models each key can use, and pick each AI's model from a dropdown (Claude Sonnet 5.5 by default).
- AI usage dashboard: spend today and this month, questions, pages, tokens and spend per model and per job, the latest runs; prices per model typed on the page.
- Reading papers: "Read this paper" on any question paper or mark scheme; the review screen shows the paper rebuilt from our database beside the PDF, with red, amber and blue flags, fixes (the PDF's version, read again, edit, It's fine, Looks right, Adjust box), Undo, and Mark ready anyway. A flag list shows every open flag by page, with filters by colour; a click, Previous and Next flag, or the J and K keys jump to one, and after a fix the next one is picked. The page and flag you were on come back when you return.
- Figures are cut straight from the PDF as SVG by code (no AI, free): the paper's own drawing, letters and symbols exact. A figure with a printed label ("Fig. 2.1") is cut above it; one without is found by its labels and flagged blue to check. "Adjust box" lets you drag a new box on the page, or use the whole page. Each figure also gets a short written description for the brain. Every read paper gets a read accuracy badge (green, amber or red with its %), from how well the AIs read it by themselves the first time: on the review screen, beside Review on the session page, and in "Papers read" on the subject overview (weakest first). The reading buttons ask "Proceed?" first, with the cost. "Cut figures from the PDF (free)" cuts them again with no AI (useful for papers read before this). Admin only: Cambridge's pictures are never shown to students.
- Live progress for brain runs: each step and model, tokens and time, updating in place.
- Read accuracy of each reading: the reading card lists every full reading's score with the Claude and Gemini models that read it, so a cheaper model can be compared with the one in use on the same paper. A mark scheme's marks checked against its question paper count in the score.
- Reading AI: its own Claude model for reading question papers and mark schemes (AI setup), so a cheaper model such as Claude Haiku 5.5 can read papers while topic trees keep the main AI. Until chosen it is the main AI. Haiku's price is set (0.10 and 0.50 dollars per million tokens).
- Drawing AI: its own Claude model, kept for drawing our own figures for new questions (step 3); paper reading no longer uses it.
- Topic tree runs read with Gemini first (free) and Claude second, retry when Google is overloaded, and keep finished readings so a failed run is never paid for twice.
- Monthly spending cap: a run whose rough cost would pass it does not start; the rough cost shows beside each Draft button.
- Parent approval has its own page under Students and parents.

## Coming next
- Upload a folder (Library > Upload): pick an unzipped Google Drive folder. Every PDF is worked out from its folder names, its first page and the AI, you check the preview, then the files are uploaded one at a time. Files already stored are skipped, so you can pick the same folder again later. Pre-release material (Computer Science), listening transcripts and teachers' notes (French) are recognised and stored; Every real Cambridge file of a library subject comes in, even kinds or papers the checklist does not ask for (like ICT source files), and shows as an extra. Where the AI has a guess for an unclear file it is already chosen for you. "Download report" saves a spreadsheet of every file and what happened to it. Papers Cambridge set under another code for a country series (Physics 1524, Pakistan 2021) are stored with their subject and shown in that session as their own series; a new such code is linked from the first page by itself. If a file's cover names a paper differently from the library, the page lists it.
- AI meter: the top of every admin page shows how many AI questions were asked today and about how much of the free daily allowance they used.
