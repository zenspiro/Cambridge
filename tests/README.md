# Tests

Admin pages are desktop only (owner decision, 2 Nov 2026): the admin suites run at 1400 px. Public and student pages are tested at 375 px and 1400 px.

Each browser test file must pass on its own fresh database: CI runs them in three groups side by side (`.github/workflows/ci.yml`, job `e2e`). A test that locks an address (admin.mjs: five wrong passwords) uses an address no other test can pick (`100.64.0.1`). Random test data must never land on what another test in the same group expects (library.mjs never uploads June 2024: the agent test's fake website offers those).

Rule for browser checks: after an in-place update (`ActionForm`, `router.refresh()`), wait for the new content (`locator.waitFor`), never check it the moment the message appears; CI machines are slower.

## Browser smoke test (`tests/e2e/smoke.mjs`, `npm run test:e2e`)
Needs a running Worker (`npx wrangler dev --local --port 8787`, or set `BASE_URL`). Public pages at 375 px and 1400 px, admin pages (sign-in) at 1400 px only: right status, has an h1, no sideways scroll, no script or console errors (CSP violations show here), every script carries the nonce. Add new pages to `PAGES`.

## Admin sign-in test (`tests/e2e/admin.mjs`, part of `npm run test:e2e`)
Needs a running Worker and `.dev.vars` (copy `.dev.vars.example`). The full sign-in and sign-out flow at desktop width (admin is desktop only), cookie flags, replayed cookie, cross-site and Origin-less POSTs, forged cookie, and the lockout. Each run uses made-up networks (`cf-connecting-ip`), so lockouts do not carry over between runs.

## Library test (`tests/e2e/library.mjs`, part of `npm run test:e2e`)
Needs a running Worker with migrations applied and `.dev.vars`. Upload (good, bad name, fake PDF), library home (qualifications, subject cards, search), subject overview (breadcrumb, grid, papers, routes, kept short), session and version pages, described search results and download, junk filters, Missing filter, per-syllabus essential variants, adding a missing file (unapproved link refused, upload with any name), sources (add, refused address, switch off, inline confirm, remove) at desktop width (admin is desktop only), and signed-out and cross-site attempts on every library page and POST. Uses a random valid file name each run; re-running is safe. Click buttons by their form, not by `button[type=submit]`: the header's Sign out button comes first. Find messages with `p.alert` / `p.notice`, not `[role=alert]`: Next adds a hidden route announcer with that role.

## Agent test (`tests/e2e/agent.mjs`, part of `npm run test:e2e`)
Needs a running Worker, migrations and `.dev.vars` (with `AGENT_SECRET`). Starts a fake source website (`fake-source.mjs`, port 9911), switches Cambridge's source off for the test, sets up runs in the local D1, runs `scripts/agent/run.ts` in test mode (http allowed only for localhost, 50 ms gaps), and checks the reports (described in words, grouped by session, "Library after this run"), the library, live feedback (progress bar, auto-refresh, activity log in plain words), cancelling a run mid-way, the never-started warning, a fake Google Drive API (folder paste, reading folders and naming files, private folder, key only in a header, download, Sources summary), "Needs your eye" (reject, undo, accept as a checklist file, the download fetches it under that name, a rejected file is skipped next run), the front page reader (an unnamed Drive file named from its cover, a misnamed one stored under its cover name, the library check finds and renames a mismatch), the settings page and attacks on the signed endpoints. Run the agent with async `spawn`, never `spawnSync`: the fake site lives in the test process. It never contacts Cambridge. Its local database helper retries up to 3 times (Wrangler's local tool can fail once while the dev server holds the file). A website with no start page for the subject: the agent follows its menus (qualification, subject by code, the run's session) to files inside download links, keeps only essential files with the option on, says where it found the subject, and opens no other year, subject, viewer page or file. An upload's declared SHA-256: bytes that do not match it are refused with nothing kept, the right one is stored.

Without Workers AI locally, it checks the page says so.
